# 本地埋点与首测口径

当前 `AnalyticsService` 只把最多 256 个事件留在内存。没有网络请求、追踪 Cookie、用户姓名或账号。设置页可手动导出本次会话 JSON。刷新将开始新会话；它不是跨日留存统计系统。测试种子和 debug 会话必须排除正式指标。

| 事件 | 实际触发位置／字段 |
|---|---|
| game_open | 页面成功初始化；版本、平台名称 |
| tutorial_start | 尚未完成教程的用户开启一局 |
| tutorial_complete | 第一次合法发射完成，不等于真人完全理解 |
| run_start | 新局／续局；runId、种子、模式、店长、resume |
| first_action | 本局第一发；打开本局后有效游玩秒数 |
| upgrade_select | 选择、跳过补血；改装 ID、等级与下一波次 |
| run_end | 胜败或主动结束；分数、波次、连击、有效局时长、构筑 |
| restart | 结算页再开；是否同种子 |
| progression_unlock | 结算时解锁店长 |
| share_card_create | 在本机成功生成 PNG，不等于成功发送或带来新用户 |

`activeSeconds` 包含瞄准和选牌，排除暂停与后台；“×3 演出”会缩短墙钟时长但不改变同角度的固定步物理。纯模拟的 `flightSeconds` 只累计飞行，两者不能混用。

## 先验证这三个数据

**首局闭环完成率**：首次 `run_start(resume=false)` 后，能看到一次 `run_end` 的人数／首次开局人数。应另外拆分通关、战败、主动收摊和直接离开，不能把“通关率”与“完成率”混淆。当前导出跨页面丢失事件，首测应结合旁观记录；接在线统计后再去重。

**第二局开启率**：首局结束后同一观察会话中主动开始第二局的人数／已结束首局的人数；从主页再次开始也计入，不只统计 `restart` 按钮。它比脚本能不能通关更接近重玩意愿。

**完整一局有效时长分布**：按首局／复玩、模式、演出速度、胜败拆分，报告中位数与尾部，另记瞄准、选牌、等待的具体卡点。不只报一个平均数。

设计目标“5—10 秒理解”“2—4 分钟普通局”均是待验证假设；没有套用未经来源核验的行业阈值。少量受访者适合定位问题，不足以宣称统计显著或预测爆款。正式做不同版本比较时，一次只改一个主要变量，保留分母与原始数据，预先确定观察窗口。

接第三方统计前需要实际 SDK、同意流程、隐私说明与删除策略；不要直接把全部本地事件连同种子、账号和设备资料上报。
